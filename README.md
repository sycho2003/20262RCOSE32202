## 1. 운영체제의 역할

운영체제는 프로그램이 하드웨어 자원을 사용할 수 있도록 관리합니다.
CPU 실행 시간, 메모리, 파일, 입출력 장치를 관리하며 프로그램 사이의 자원 충돌을 조정합니다.
여러 프로그램이 함께 실행될 때 각 프로그램을 보호하는 것도 중요한 역할입니다.

## 2. 사용자 모드와 커널 모드

사용자 프로그램은 제한된 권한의 사용자 모드에서 실행됩니다.
커널은 특권 명령을 실행할 수 있는 커널 모드에서 자원을 관리합니다.
사용자 프로그램은 시스템 호출을 통해 파일 읽기나 프로세스 생성 같은 커널 서비스를 요청합니다.
시스템 호출 시 제어가 커널로 넘어가지만, 반드시 다른 프로세스로 전환되는 것은 아닙니다.

## 3. 인터럽트와 예외

하드웨어 인터럽트는 장치의 입출력 완료나 타이머 이벤트처럼 CPU 실행 흐름 밖에서 발생한 사건을 알립니다.
예외는 현재 실행 중인 명령과 관련해 동기적으로 발생하며, 잘못된 메모리 접근 등이 그 예입니다.
운영체제는 필요한 실행 상태를 보존한 뒤 해당 처리 루틴을 수행합니다.

## 4. 프로세스와 문맥 교환

프로세스는 실행 중인 프로그램이며, 주소 공간과 레지스터 상태 등 실행에 필요한 문맥을 갖습니다.
대표적인 상태에는 준비, 실행, 대기가 있습니다.
문맥 교환은 실행 중인 프로세스의 상태를 저장하고 다른 프로세스의 상태를 복원하는 과정입니다.
이 과정에도 시간이 들기 때문에 문맥 교환 비용을 고려해야 합니다.

## 5. CPU 스케줄링

CPU 스케줄러는 준비 상태의 프로세스 중 다음에 실행할 대상을 선택합니다.

| 방식 | 기본 원리 | 고려할 점 |
| --- | --- | --- |
| FCFS | 준비 큐에 먼저 도착한 순서로 실행 | 긴 작업 뒤에서 짧은 작업이 오래 기다릴 수 있음 |
| SJF | 예상 CPU 실행 시간이 짧은 작업을 우선 선택 | 다음 CPU 실행 시간을 예측해야 함 |
| Round Robin | 정해진 시간 할당량만큼 번갈아 실행 | 할당량이 작으면 문맥 교환 횟수가 늘어날 수 있음 |

반환 시간은 도착부터 완료까지, 응답 시간은 도착부터 첫 응답까지 걸린 시간입니다.
대기 시간은 준비 큐에서 CPU를 기다린 시간의 합입니다.

## 6. 프로세스 간 통신과 동기화

프로세스 간 통신(IPC)은 프로세스들이 데이터를 주고받는 방법입니다.
공유 메모리는 같은 메모리 영역을 통해 데이터를 교환하고, 메시지 전달은 송수신 연산으로 통신합니다.
공유 자원에 동시에 접근하면 경쟁 상태가 생길 수 있으므로 임계 구역을 보호해야 합니다.
뮤텍스나 세마포어 같은 동기화 수단을 사용할 때는 교착 상태의 가능성도 고려합니다.
